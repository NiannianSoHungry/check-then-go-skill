# check-then-go Skill

AI Agent 通用交互流程规范，定义了从需求分析到执行验收的完整 15 步状态机。

## 概述

本 Skill 为 AI Agent 提供了一套标准化的工作流程，确保在处理任何有副作用的任务时，都能：
- 充分理解用户需求
- 提供多种解决方案
- 获得用户明确确认
- 安全地执行操作
- 完整地验收结果

## 适用场景

任何涉及以下操作的任务都应使用此工作流：
- 文件创建、修改、删除
- 代码编写、重构
- CSS/样式调整
- 系统配置变更
- 文档编辑
- 数据处理
- 部署操作

## 核心流程

### 阶段一：需求确认
1. 复述用户需求
2. 列出理解要点
3. 请用户确认

### 阶段二：方案设计
- 提供 2-3 个解决方案
- 每个方案标注：实现方式、工作量、风险、复杂度

### 阶段三：方案细化
- 用户选定方案
- Agent 反诘实施细节
- 给出完整实施方案

### 阶段四：执行
- 修改前创建检查点
- 一步一确认
- 实时报告进度

### 阶段五：验收
- 用户验收结果
- 失败则回滚重试（最多 3 次）

## 版本控制策略

每次执行任务前：

~~~bash
git add -A && git commit -m "检查点：[描述即将进行的操作]"
~~~

重大修改时额外创建备份：

~~~
backups/YYYYMMDD_HHMMSS/
~~~

## 四条执行纪律

1. **先解释再动手**：任何操作前必须说明做什么、为什么、影响
2. **一次一步**：每次只做一个逻辑操作，完成后等待确认
3. **最简方案优先**：先试最简单的解法，不行再逐步加码
4. **所见即所得**：不接受静默修正，有问题要明确报错

## 完整示例

### 场景：修改 Dashboard 首页标题颜色

#### 阶段一：需求确认

**用户**：把首页的标题改成红色

**Agent**：
~~~
我理解你的需求是：
1. 修改 Dashboard 首页（/ 路径）的标题颜色
2. 将颜色改为红色

请确认是否正确？
~~~

**用户**：是的，但我要的是深红色，不是亮红色

**Agent**：
~~~
明白，修正理解：
1. 修改 Dashboard 首页标题颜色
2. 颜色：深红色（如 #b91c1c 或 #991b1b）

请确认？
~~~

**用户**：确认，用 #991b1b

---

#### 阶段二：方案设计

**Agent**：
~~~
解决方案：

方案 A（推荐）：修改全局 CSS
- 实现：在 static/css/style.css 中修改 .header h1 的 color 属性
- 工作量：小（1 行代码）
- 风险：低（影响范围：所有使用 .header h1 的页面）
- 复杂度：简单

方案 B：使用 inline style
- 实现：在 templates/index.html 的 h1 标签添加 style="color: #991b1b"
- 工作量：小（1 行代码）
- 风险：中（只影响首页，但不符合样式分离原则）
- 复杂度：简单

方案 C：添加新的 CSS 类
- 实现：在 style.css 添加 .title-red { color: #991b1b; }，在 h1 添加 class
- 工作量：中（2 处修改）
- 风险：低（可复用，但当前只有一处需要）
- 复杂度：中等

建议：方案 A，最简洁且符合现有架构。
~~~

**用户**：选 A

---

#### 阶段三：方案细化

**Agent**：
~~~
好的，方案 A。确认实施细节：

1. 修改文件：static/css/style.css
2. 修改位置：.header h1 选择器
3. 修改内容：color: #1e293b; → color: #991b1b;
4. 预期效果：首页标题变为深红色 #991b1b
5. 影响范围：所有使用 .header h1 的页面

是否有其他问题？如果没有，我将开始执行。
~~~

**用户**：没问题，执行吧

---

#### 阶段四：执行

**Agent**：
~~~
步骤 1/3：创建 Git 检查点

git add -A && git commit -m "检查点：修改首页标题颜色前"

输出：
[master abc1234] 检查点：修改首页标题颜色前
 0 files changed

✓ 检查点已创建

---

步骤 2/3：修改 CSS 文件

修改 static/css/style.css：
- .header h1 { ... color: #1e293b; ... }
+ .header h1 { ... color: #991b1b; ... }

✓ 修改完成

---

步骤 3/3：提交修改

git add -A && git commit -m "修改: 首页标题颜色改为深红色 #991b1b"

输出：
[master def5678] 修改: 首页标题颜色改为深红色 #991b1b
 1 file changed, 1 insertion(+), 1 deletion(-)

✓ 修改已提交
~~~

---

#### 阶段五：验收

**场景 A — 成功**

**用户**：效果正确，颜色是对的

**Agent**：
~~~
✓ 任务完成

修改摘要：
- 文件：static/css/style.css
- 修改：.header h1 的 color 从 #1e293b 改为 #991b1b
- Commit：def5678

等待新任务。
~~~

---

**场景 B — 失败 + 修正**

**用户**：标题颜色变了，但变成了亮红色，不是深红色

**Agent**：
~~~
失败反馈：颜色不符合预期（第 1 次修正尝试）

分析可能原因：
1. CSS 优先级问题：其他选择器覆盖了 color 属性
2. 浏览缓存：显示的是旧版本

我将检查并修复。
~~~

**执行修正**：发现 .header h1 a 的 color 覆盖了 .header h1。

修正：
~~~css
.header h1, .header h1 a { color: #991b1b; }
~~~

**用户**：现在是深红色了，正确

**Agent**：
~~~
✓ 任务完成（经过 1 次修正）

修改摘要：
- 文件：static/css/style.css
- 修改：
  1. .header h1 的 color 改为 #991b1b
  2. 添加 .header h1 a 的选择器覆盖
- Commit：def5678, ghi9012

等待新任务。
~~~

---

**场景 C — 3 次修正失败 → 回滚**

**Agent**（第 3 次修正后）：
~~~
第 3 次修正尝试失败。

问题分析：
- 颜色值 #991b1b 在所有浏览器中渲染为亮红色
- 可能原因：颜色值本身不符合预期

已回滚到检查点 abc1234：

git reset --hard abc1234

✓ 已回滚到修改前的状态

建议下一步：
1. 确认目标颜色值（是否需要其他深红色，如 #7f1d1d）
2. 在浏览器中预览多个深红色选项

等待你的指示。
~~~

---

## Checklist（Agent 自检清单）

每次任务前，Agent 必须确认：
- [ ] 是否已复述需求并获得用户确认？
- [ ] 是否给出了 2-3 个方案供选择？
- [ ] 是否已反诘实施细节？
- [ ] 修改前是否已 git commit？
- [ ] 重大修改是否已创建 backups 快照？
- [ ] 是否遵守了"一次一步"原则？
- [ ] 失败修正是否已超过 3 次？是否需要回滚？

## 常见错误

### 错误 1：跳过需求确认

❌ 错误做法：
~~~
用户：修改标题颜色
Agent：（直接修改 CSS）已修改完成
~~~

✓ 正确做法：先复述需求，确认理解正确

### 错误 2：修改后才创建检查点

❌ 错误做法：
~~~
Agent：
1. 修改 CSS 文件
2. git add && git commit
~~~

✓ 正确做法：
~~~
Agent：
1. git add && git commit（修改前检查点）
2. 修改 CSS 文件
3. git add && git commit（提交修改）
~~~

### 错误 3：一次性执行多个操作

❌ 错误做法：
~~~
Agent：同时修改 CSS、HTML、JavaScript 三个文件
~~~

✓ 正确做法：每完成一步，等待用户确认后再进行下一步
