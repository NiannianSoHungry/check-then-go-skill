## 适用场景

任何涉及以下操作的任务都应使用此工作流：

- 文件创建、修改、删除
- 代码编写、重构
- CSS / 样式调整
- 系统配置变更
- 文档编辑
- 数据处理
- 部署操作

<blockquote>

ℹ️ **提示**：纯问答、知识检索、方案讨论等无副作用的交互**不适用**本规范。

</blockquote>

---

## 为什么需要这个 Skill？

| 痛点 | 后果 |
|------|------|
| **用户失去控制感** | Agent 擅自修改，用户不知道改了什么 |
| **改崩了无法恢复** | 没有检查点，错误只能手动逐行回退 |
| **简单问题复杂化** | 一上来就重写整个模块，其实改一行 CSS 就能解决 |

本 Skill 通过 **强制复述 → 方案对比 → 确认后执行 → 失败可回滚** 的机制，让 Agent 的每一步操作都在用户的知情和控制之下。

## 五阶段状态机

~~~

│                    🎯 阶段一：需求确认                        │
│              复述需求 → 列出要点 → 用户确认                   │
└──────────────────────────────────┬──────────────────────────┘
                                   ▼
┌─────────────────────────────────────────────────────────────┐
│                    🧠 阶段二：方案设计                        │
│              分析现状 → 2-3个方案 → 回答疑问                  │
└──────────────────────────────────┬──────────────────────────┘
                                   ▼
┌─────────────────────────────────────────────────────────────┐
│                    🔍 阶段三：方案细化                        │
│              选定方案 → 反诘细节 → 完整实施方案               │
└──────────────────────────────────┬──────────────────────────┘
                                   ▼
┌─────────────────────────────────────────────────────────────┐
│                    ⚙️ 阶段四：安全执行                        │
│           git检查点 → 逐步执行 → 实时报告                     │
└──────────────────────────────────┬──────────────────────────┘
                                   ▼
┌─────────────────────────────────────────────────────────────┐
│                    ✅ 阶段五：验收交付                        │
│              用户验收 ──成功──→ 结束，等待新需求              │
│                  │                                             │
│                  └─失败─┬─→ 回到阶段二重新分析（最多3次）     │
│                        └─→ 3次全部失败 → git reset --hard   │
│                                         回滚到检查点         │
└─────────────────────────────────────────────────────────────┘
~~~

<a name="四条执行铁律"></a>

## 四条执行铁律

### 铁律一：先解释再动手

任何操作前，必须说明：**做什么、为什么、有什么影响**。

❌ **错误**
~~~
用户：把标题改成红色
Agent：（直接修改）已改好
~~~

✅ **正确**
~~~
Agent：我理解你的需求是修改首页标题为红色，方案是修改 CSS 中的 color 属性。
现在执行修改，影响范围是所有使用 .header h1 的页面。
~~~

---

### 铁律二：一次一步，逐步确认

每次只做**一个逻辑操作**，完成后等待用户确认，再进行下一步。

❌ **错误**
~~~
Agent：同时修改了 CSS、HTML、JS 三个文件
~~~

✅ **正确**
~~~
Agent：步骤 1/3：修改 CSS 文件 ✓
Agent：步骤 2/3：更新 HTML 引用 ✓
Agent：步骤 3/3：调整 JS 交互 ✓
~~~

---

### 铁律三：最简方案优先

遇到问题先试最简单的解法，确认不行再逐步加码。

---

### 铁律四：所见即所得

不接受静默修正。用户输入是什么就是什么，有问题要明确报错。

## 版本控制速查

**日常修改**（1-3 个文件、少量代码）：

```bash
git add -A && git commit -m "检查点：[描述即将进行的操作]"
# 执行修改
git add -A && git commit -m "修改：[具体描述]"
```

**重大修改**（重构模块、跨 5+ 文件、删除功能）：

```bash
# 1. git 检查点
git add -A && git commit -m "检查点：[描述]"

# 2. 目录快照
cp -r {PROJECT_DIR} {BACKUP_DIR}/YYYYMMDD_HHMMSS/

# 3. 执行修改
# 4. git 提交最终版本
```

**回滚操作**：

```bash
git reset --hard {检查点的 commit hash}
```

## 三大常见陷阱

### 陷阱一："修复很简单"跳步综合症 ⚠️ 最高频！

**症状**：修复看起来显而易见（如一行 CSS、一个明显 bug），Agent 直接执行，跳过复述、方案对比、确认、<kbd>git commit</kbd> 检查点。

**后果**：用户失去控制感；修复失败时没有回滚点；信任度持续下降。

<blockquote>

⚠️ **对策**：无论修复多简单，**必须在执行前口头确认 + 创建 git 检查点**。<br>
"简单"不是跳步的理由。

</blockquote>

---

### 陷阱二：修改后才补 git commit

**症状**：先改文件，再 <kbd>git add</kbd> && <kbd>git commit</kbd>，认为"反正提交了就行"。

**后果**：无法通过 <kbd>git reset --hard</kbd> 回滚到修改前的干净状态。

<blockquote>

⚠️ **对策**：**修改前**必须先 commit 创建检查点，修改完成后再提交最终版本。

</blockquote>

---

### 陷阱三：备份与 git 检查点混淆

**症状**：认为 <kbd>git commit</kbd> 就是备份，重大修改也不创建目录快照。

**后果**：git 只能回滚代码，无法保留生成的文件、临时数据等完整项目状态。

<blockquote>

⚠️ **对策**：日常小改 → 只做 git commit；重大修改 → <kbd>git commit</kbd> + 目录快照双重保护。

</blockquote>

## Agent 自检 Checklist

每次任务前，必须逐项确认：

- [ ] 是否已复述需求并获得用户确认？
- [ ] 是否给出了 2-3 个方案供选择？
- [ ] 是否已反诘实施细节？
- [ ] 修改前是否已 <kbd>git commit</kbd> 创建检查点？
- [ ] 重大修改是否已创建 backups 目录快照？
- [ ] 是否遵守了"一次一步"原则？
- [ ] 失败修正是否已超过 3 次？是否需要回滚？

### 场景：修改 Dashboard 首页标题颜色

#### 阶段一：需求确认

**用户**：把首页的标题改成红色

**Agent**：
~~~
我理解你的需求是：
1. 修改 Dashboard 首页（/ 路径）的标题颜色
2. 将颜色改为红色

请确认是否正确？
~~~

**用户**：是的，但我要的是深红色，不是亮红色

**Agent**：
~~~
明白，修正理解：
1. 修改 Dashboard 首页标题颜色
2. 颜色：深红色（如 #b91c1c 或 #991b1b）

请确认？
~~~

**用户**：确认，用 #991b1b

---

#### 阶段二：方案设计

**Agent**：
~~~
解决方案：

方案 A（推荐）：修改全局 CSS
- 实现：在 static/css/style.css 中修改 .header h1 的 color 属性
- 工作量：小（1 行代码）
- 风险：低（影响范围：所有使用 .header h1 的页面）
- 复杂度：简单

方案 B：使用 inline style
- 实现：在 templates/index.html 的 h1 标签添加 style="color: #991b1b"
- 工作量：小（1 行代码）
- 风险：中（只影响首页，但不符合样式分离原则）
- 复杂度：简单

方案 C：添加新的 CSS 类
- 实现：在 style.css 添加 .title-red { color: #991b1b; }，在 h1 添加 class
- 工作量：中（2 处修改）
- 风险：低（可复用，但当前只有一处需要）
- 复杂度：中等

建议：方案 A，最简洁且符合现有架构。
~~~

**用户**：选 A

---

#### 阶段三：方案细化

**Agent**：
~~~
好的，方案 A。确认实施细节：

1. 修改文件：static/css/style.css
2. 修改位置：.header h1 选择器
3. 修改内容：color: #1e293b; → color: #991b1b;
4. 预期效果：首页标题变为深红色 #991b1b
5. 影响范围：所有使用 .header h1 的页面

是否有其他问题？如果没有，我将开始执行。
~~~

**用户**：没问题，执行吧

---

#### 阶段四：执行

**Agent**：
~~~
步骤 1/3：创建 Git 检查点

git add -A && git commit -m "检查点：修改首页标题颜色前"

输出：
[master abc1234] 检查点：修改首页标题颜色前
 0 files changed

✓ 检查点已创建

---

步骤 2/3：修改 CSS 文件

修改 static/css/style.css：
- .header h1 { ... color: #1e293b; ... }
+ .header h1 { ... color: #991b1b; ... }

✓ 修改完成

---

步骤 3/3：提交修改

git add -A && git commit -m "修改: 首页标题颜色改为深红色 #991b1b"

输出：
[master def5678] 修改: 首页标题颜色改为深红色 #991b1b
 1 file changed, 1 insertion(+), 1 deletion(-)

✓ 修改已提交
~~~

---

#### 阶段五：验收

**场景 A — 成功**

**用户**：效果正确，颜色是对的

**Agent**：
~~~
✓ 任务完成

修改摘要：
- 文件：static/css/style.css
- 修改：.header h1 的 color 从 #1e293b 改为 #991b1b
- Commit：def5678

等待新任务。
~~~

---

**场景 B — 失败 + 修正**

**用户**：标题颜色变了，但变成了亮红色，不是深红色

**Agent**：
~~~
失败反馈：颜色不符合预期（第 1 次修正尝试）

分析可能原因：
1. CSS 优先级问题：其他选择器覆盖了 color 属性
2. 浏览缓存：显示的是旧版本

我将检查并修复。
~~~

**执行修正**：发现 .header h1 a 的 color 覆盖了 .header h1。

修正：
```css
.header h1, .header h1 a { color: #991b1b; }
```

**用户**：现在是深红色了，正确

**Agent**：
~~~
✓ 任务完成（经过 1 次修正）

修改摘要：
- 文件：static/css/style.css
- 修改：
  1. .header h1 的 color 改为 #991b1b
  2. 添加 .header h1 a 的选择器覆盖
- Commit：def5678, ghi9012

等待新任务。
~~~

---

**场景 C — 3 次修正失败 → 回滚**

**Agent**（第 3 次修正后）：
~~~
第 3 次修正尝试失败。

问题分析：
- 颜色值 #991b1b 在所有浏览器中渲染为亮红色
- 可能原因：颜色值本身不符合预期

已回滚到检查点 abc1234：

git reset --hard abc1234

✓ 已回滚到修改前的状态

建议下一步：
1. 确认目标颜色值（是否需要其他深红色，如 #7f1d1d）
2. 在浏览器中预览多个深红色选项

等待你的指示。
~~~
